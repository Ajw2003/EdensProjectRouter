# Android app

Step 8 of the companion plan (issue #38, parent #35). The same screens as the PC app, as an APK, built on GitHub. Built; the APK itself has not been built or run (see "Not verified").

## What it owns

- A Capacitor project in `android-app/` (app id `com.edens.router`, name "Edens Router", APK `EdensRouter.apk`). Capacitor is a toolkit that wraps web screens in an Android WebView.
- The app's own local page (`android-app/www/index.html`, `app.js`): scan the pairing QR code, remember the PC, open it.
- A script injected into the PC's page (`android-app/www/remote.js`): the Esc / up / down / Enter key row and the Needs-you phone notifications.
- `.github/workflows/android.yml`.

It does not own the screens or the server. Those come from step 7 (the phone link, port 47213).

## How it works

1. First run: the camera opens and jsQR reads frames from a canvas. The QR holds `http://<address>:47213/pair#<code>`. The app saves the base address (`http://<address>:47213`, never the code) in localStorage key `edens.base`, then moves the WebView to the pair URL. Step 7's server sets its cookie and redirects to `/`. A large Cancel button and a "Type the address instead" box sit on the same screen.
2. Later starts: the app asks the saved address for `/`. If it answers within 5 seconds the WebView goes there. If not, "Can't reach your PC" with Try again and Scan again.
3. The WebView may leave the local page for any address (`server.allowNavigation: ["*"]`) and may use plain HTTP (`server.cleartext`, `android:usesCleartextTraffic`), because home Wi-Fi has no certificate.
4. `MainActivity.java` runs `remote.js` in every page finished loading that is not the local page.
5. `remote.js`:
   - Key row: a fixed bottom row shown while a `.xterm` terminal is visible. Keys send `\x1b`, `\x1b[A`, `\x1b[B`, `\r` through `window.routerDesktop.ptyWrite` to the pty the page last wrote to or opened (it wraps `ptyWrite` and `ptyOpen` to learn it). No change to `site/`.
   - Notifications: it wraps `EventSource` so every stream the page opens also listens for the Needs-you event, then shows it with `@capacitor/local-notifications`. The event name is the constant `NEEDS_YOU_EVENT` at the top of `android-app/www/remote.js` (set to `needs-you`, a guess until step 7's name is known). The payload is read as JSON `{text, key}`, or plain text. Tapping the notification calls the page's own `onNotifyClick` handler with the key, which opens that session.
   - Permission: once, with one sentence ("Allow notifications so your phone can tell you when a session needs you."), then Android's own Android 13+ prompt.

## Background

The link stays open while the app is in the background only as far as Android allows with no foreground service. Android may pause the WebView a few minutes after the app leaves the screen, and then Needs-you notifications stop until the app is opened again. The upgrade is a foreground service with a persistent notification; it is marked `shortcut:` in `MainActivity.java`.

## Workflow

`android.yml` runs on a push to any branch, on `v*` tags and by hand. ubuntu-latest, Temurin 21, `android-actions/setup-android`; then `npm ci`, `npx cap sync android` (in `android-app`) and `./gradlew assembleDebug` (in `android-app/android`). It uploads `EdensRouter.apk` as the artifact `edens-router-apk` and on a `v*` tag attaches it to the Release. The APK is debug-signed, which is fine for the prototype: it installs by sideloading, and cannot go in the Play Store.

## Traps

- `www/jsQR.js` is a copy of `node_modules/jsqr/dist/jsQR.js` (jsqr 1.4.0). Copy it again if the version changes.
- `android/app/src/main/assets/public` and `capacitor.config.json` there are generated by `cap sync` and git-ignored; CI regenerates them. `android/app/capacitor.build.gradle` and `android/capacitor.settings.gradle` are committed.
- Editing `remote.js` needs no Java change, but it only reaches the phone after a new APK.
- The key row cannot know which pane has focus: it writes to the last pty the page used. Before you type anything in a terminal, it uses the last one opened.
- The key row and notification path rely on the page's `routerDesktop` having `ptyWrite`, `ptyOpen` and `onNotifyClick`, and on the server using Server-Sent Events. If step 7 differs, change `remote.js`.
- `node_modules/` is not committed (`android-app/.gitignore`).

## Checks

`android-app/scripts/check-local.cjs` drives `www/` in Chromium at 390x844 with a canvas as a fake camera, needing `playwright` and `qrcode` on `NODE_PATH`. It checks: a QR of a known pair URL is decoded, the base saved without the code, the WebView sent to the pair URL; a typed address; a later start going straight to the saved address; "Can't reach your PC" for a refused address and for one that never answers (after 5 s). Screenshots: `docs/generated/android-*.png`.

## Not verified

- The APK was not built: this machine cannot download the Android SDK (`dl.google.com` refused) and has no emulator. `MainActivity.java` and the Gradle change (`EdensRouter.apk` name) have never been compiled; the first GitHub run is their first test.
- `remote.js` was not run in a WebView or against step 7's server: not the Capacitor bridge calls (`nativePromise`, `addListener`), not the injection, not notifications, not the tap, not the key row.
- The real camera was not used, only a canvas stand-in.
- Android's camera and notification permission prompts, and the background pause, were not seen.
