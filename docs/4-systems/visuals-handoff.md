# Visuals and hand-off

**Status: planned.** Approved on 2026-10-18 ("Design approved: router visuals and handoff 1A 2A 3C 4* 5*"). Build contract: `docs/plans/router-grid-spec.md`, sections 5 to 8. Windows app only.

## What it owns

- The Visuals tile for each project: pictures, video, PDF, Markdown and web pages that its sessions write or show, and claude.ai artifact links.
- The Show tool, a small MCP server that lets Claude put a file on screen on purpose.
- Sending a page's copied reply into the session that made it.
- Send to: files, pages and conversations into an open session, a new session or a sub-session (a `--fork-session` branch).
- Ask another session: free by default, or a read-only copy that spends usage when Aj chooses it.
- The `.router-handoff` folder in each receiving project and its "Keep hand-off files out of git" toggle.

## How it works

- Visuals are found from transcript tool calls (`Write`, `Edit`, `MultiEdit`, `NotebookEdit`) by file extension, plus Show tool entries from `%APPDATA%\Project Router\shows.jsonl`.
- Web pages run in a walled-off webview with no Node access. Its preload reports text the page copies, which adds the Send button.
- Sent text is typed into the session's terminal without Enter, so Aj always presses Enter.
- Usage-spending runs (summary, Ask's read-only copy) use `claude -p --resume <id> --fork-session --no-session-persistence --tools Read,Grep,Glob`, so the source session is never changed. The prompt or question is written to Claude Code's stdin, never put on the command line: after `--tools` (which takes a list) Claude Code 2.1.302 read it as a tool name and stopped with "Input must be provided", and a Windows `.cmd` launcher runs through `cmd.exe`, which cannot carry `& | < > ^ % "` and line breaks safely. Claude Code 2.1.302 was checked here reading a `-p` prompt with all of those characters from stdin, unchanged.

Issue #22 (2026-10-18), branch `AjsAgent/ask-22`: Ask another session. The session tile ⋯ menu has "Ask another session…" (`site/js/askdialog.js`; pure rules in `site/js/ask.js`; `buildAskCommand` in `desktop/launch.js` shares one builder with the summary run; `ask` in `desktop/handoff.js`). The dialog has a searchable picker (all accounts, newest first, the asking session left out) and a question box. "Send the conversation with my question" writes the picked session's cleaned copy into the asking project's `.router-handoff/` and types `@<file> <question>` with no Enter (line breaks in the question become spaces, because a typed line break is Enter). "Ask a read-only copy" runs `claude -p "<question>" --resume <id> --fork-session --no-session-persistence --tools Read,Grep,Glob` in the other session's folder with its account folder, writes `<date>-answer-<slug>.md` in the asking project and types `@<file> `. Its label shows that account's 5-hour and weekly use; it is disabled with the reason under it at 5-hour 100%, and with no reading until "Ask without a limit reading" is ticked (this dialog only; it never overrides 100%). A working notice shows during the run; a failure notice carries the first line of stderr. The question goes in on stdin exactly as typed on every platform, so a Windows `.cmd` launcher run through `cmd.exe /d /s /c` never sees it. Driven here (fake claude, three fake accounts): free path, read-only path, 100% disabled, no-reading disabled then enabled by the checkbox, a failing run; screenshot `docs/generated/ask.png`. Not run: real Claude Code, a real Windows `.cmd` launcher.

## Traps

- `.router-handoff` is kept in git by default because Aj backs projects up with git; the toggle edits `.git/info/exclude`, which git never commits.
- Claude Code never draws pictures in a terminal, so a terminal image add-on would not help; visuals come from files.
